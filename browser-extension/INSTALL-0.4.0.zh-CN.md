# 安装浏览器预览 0.4.0

本次更新的是浏览器扩展，**不能把 ZIP 上传到 Dify 插件管理页**。它不会更新或替换 Brian 的 hu8627/dmn_json 插件，也不会修改 Dify Web 服务端。

1. 下载本 Release 的 dmn-browser-preview-0.4.0.zip，核对 SHA256SUMS.txt 后解压。
2. 在组织允许的浏览器扩展安装方式下加载此目录。使用开发者模式加载解压扩展时，按浏览器/组织要求批准；已有旧版加载目录可替换文件后重新加载。
3. 刷新 Dify 工作流页面，点击扩展图标，再点击 DMN 节点。内联 JSON、definition bundle 或 XML 可直接预览。刷新或切换编辑应用后需再次启用。
4. 存储节点的表体不在页面内。可以导入已保存 JSON，或由维护者配置下述只读查询应用。

## 自动读取存储表

维护者在**同租户、同插件身份**下导入 reader-latest.yml 和 reader-version.yml。将每个模板的 REPLACE_TABLE_NAME 改为允许读取的固定表名，再审核发布。模板不提供 op/table/body_json 输入；调用者只可传版本号。

使用组织现有的应用访问控制，让需要看表的人能调用查询应用，但不能修改查询图。不要照搬本地合成测试的匿名访问，不要提供管理员或 Service API key。

维护者按 reader-connections.example.json 填写：当前 Dify origin、编辑应用 UUID、表名、查询应用 site code/readAppId、已发布 workflow UUID。它们是绑定信息，不应填写任何口令或 token。模板中的插件依赖固定到验证过的 Brian 0.5.18，升级时需重新核对。

在扩展面板选择连接文件，点击“启用查询与自动读取”。随后同一编辑应用内切换节点会自动查询并核对表名、版本与摘要；关闭面板、刷新或换应用后连接失效。

查询会运行专用工作流并产生记录，不运行当前业务节点。维护者必须保持查询图只读。扩展在运行后核对发布版本，变更会拒绝展示，但不能撤销已经发生的执行。

只有摘要、没有版本号的节点目前只核对当前版本，不搜索历史 50 版。身份交换失败、无表体、版本或摘要不符都会报错，不改走编辑接口或回退到其他版本。

## 验证边界

原版 Dify 1.11.1、Brian 0.5.18 和真实 MV3 的隔离链已验证。测试使用仅限一次性本地实例的签名例外，不是关闭公司签名校验的建议。定制部署的 SSO、存储分域、API 路径及权限需在目标环境确认。

本次交付位于 dify-workbench-111 仓库。其现有 CLI/MCP 功能保留；不附带自制 Dify DMN 插件。查询模板是普通 Dify 工作流，调用已安装的 Brian 插件，不需要安装新的 .difypkg。
